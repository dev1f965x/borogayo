# borogayo (보러가요)

[English](./README.md) | [한국어](./README.ko.md)

집 보러 다닐 때 쓰는 모바일 앱. 목록을 만들고, 무엇을 볼지 먼저 정해두고, 보러 간 집마다 같은 기준으로 점수를 매깁니다. 다섯 군데쯤 보고 나면 어디가 어땠는지 기억이 뭉개지는데, 그걸 기록으로 대체하는 게 목적이에요.

![Dart](https://img.shields.io/badge/Dart-3-0175C2?logo=dart&logoColor=white)

UI는 한국어 전용이고, 범용 체크리스트가 아니라 **주택 한정**으로 일부러 좁혔습니다. 채광·소음·수압·곰팡이·교통 같은 기본 항목이 미리 들어있는 게 핵심이에요 — "항목을 직접 정의하세요"라는 빈 화면이야말로 범용 도구가 안 쓰이게 되는 이유라서요.

## 기능

- **목록** — 이사 한 번에 하나씩 (예: "2026 봄 이사"). 이름을 받고 이어서 평가 기준을 정하는데, 집 볼 때 흔히 확인하는 것들이 미리 채워져 있습니다. 나중에 수정 가능.
- **건물은 묶음, 평가 대상은 방** — 같은 건물에서 방 여러 개를 보는 경우가 많아서 건물로 한 번 묶지만, 건물 자체를 고르는 건 아닙니다. 그래서 `방 추가`가 기본 동작이고(건물은 그 안에서 고르거나 바로 만듭니다), 건물은 공통 평가를 매기고 사진을 붙이는 **관리 화면**으로 따로 뺐습니다.
- **하는 일이 다르면 탭으로** — 건물 기준과 방 기준, 건물 채점과 방 목록은 각각 탭으로 나뉩니다. 이어 붙이면 방 하나 보려고 채점 항목 전부를 스크롤해 지나가야 하고, 지금 어느 쪽을 보고 있는지도 흐려집니다.
- **기준을 건물용/방용으로 분리** — 교통·주차·엘리베이터 같은 건물 기준은 **건물마다 한 번만** 매기고, 채광·소음·수압 같은 방 기준은 방마다 매깁니다. 안 나누면 "역 도보 8분"을 방마다 다시 매기게 되고, 그때마다 값이 미묘하게 달라져요.
- **두 가지 기준 유형** — **점수형**(0~10 슬라이더, 0.5 단위) 또는 **여부형**(있음/없음). 둘 다 같은 0~10 척도로 저장되므로(없음=0, 있음=10) 가중합산 공식 하나로 전부 커버됩니다. 유형은 이름을 적은 **뒤에** 묻습니다 — 입력줄 옆에 늘 띄워두면, 정할 게 생기기도 전에 정하라는 셈이라서요.
- **중요도** — 기준마다 1~5. 통근이 채광보다 더 크게 반영되도록 조절할 수 있어요.
- **목록이 곧 순위, 순위의 단위는 방** — 목록 화면은 건물을 가로질러 **방을 한 줄로** 세웁니다. 계약하는 대상이 "대성빌라"가 아니라 "대성빌라 302호"라서요. 건물에는 점수가 없고, 건물 기준 점수는 그 안 방들의 점수에 합산돼 들어갑니다. 상위 3칸에 메달, 동점이면 가나다순. 순위를 별도 탭으로 빼두면 "그래서 지금 어디가 1등이지"를 볼 때마다 화면을 옮겨야 하는데, 그게 이 앱이 존재하는 유일한 질문이라서 목록 자체를 순위로 뒀습니다.
- **이모지(선택)** — 기준에 이모지를 달 수 있고, 이름을 보고 알아서 골라줍니다. 채점 화면이 길어져도 눈으로 훑을 수 있게요.
- **사진 · 영상** — 건물이나 방에 현장에서 찍어 붙이고, 구역(외관·주방·화장실… 없으면 직접 입력)을 태그로 달아 걸러 볼 수 있습니다. 영상은 추가할 때 첫 장면을 뽑아 썸네일로 보여줍니다.
- **전부 고칠 수 있음** — 목록·건물·방 이름과 메모, 평가 기준의 이름·이모지·유형, 사진이 붙은 위치와 구역, 잘못 매긴 점수까지 나중에 되돌릴 수 있습니다. 현장에서 급히 입력하는 앱이라 오타와 오선택이 기본값에 가깝고, 고칠 수 없는 항목이 하나라도 있으면 결국 지우고 다시 만들게 됩니다. 점수형↔여부형처럼 이미 매긴 값의 뜻이 달라지는 변경은 어떻게 바뀌는지 먼저 알리고 진행합니다.
- **공유** — 파일 그대로 다른 앱에 넘기고, `대성빌라 302호 · 거실 2, 주방` 한 줄은 **클립보드에** 담아둡니다. 받는 쪽에서 곤란한 건 "이게 어느 집 사진이냐"인데, 안드로이드 공유에 텍스트를 같이 실으면 파일이 있을 때 그걸 버리는 앱이 많습니다(카카오톡). 어떤 앱은 받고 어떤 앱은 버리면 보내는 사람이 결과를 예측할 수 없어서, 아예 파일만 보내고 설명은 붙여넣게 했습니다. 여러 장을 보낼 때는 걸어둔 구역 필터가 그대로 고르는 도구가 됩니다.
- **설정** — 밝게/어둡게/시스템 설정 따르기(기기에 저장), 앱 버전, 데이터 전체 삭제.

방 삭제는 스낵바에서 되돌릴 수 있고, 점수와 사진까지 함께 복구됩니다. 나머지는 전부 한 번 더 묻습니다 — 삭제 버튼은 처음 누르면 빨갛게 펼쳐지기만 하고 두 번째 눌러야 지워지며, 목록·건물·평가 기준처럼 여파가 큰 삭제는 거기에 확인까지 받습니다. 채점 화면을 저장 없이 나가려 하면 한 번 물어봅니다.

모든 데이터는 기기 안에만 저장됩니다. 계정도, 서버도, 네트워크도 없어요.

## 데이터 모델

평가 기준이 목록마다 다르게 정의되므로, 점수를 통짜 JSON이 아니라 관계형으로 저장합니다. 그래야 나중에 가중치만 바꿔서 순위를 다시 계산해도 저장된 점수를 건드릴 필요가 없어요. 건물 점수와 방 점수는 테이블을 나눴는데, 한 테이블에 담으면 소유자 컬럼이 둘 다 널 허용이 되어 읽을 때마다 "어느 쪽 점수인지"를 확인해야 하기 때문입니다.

```
projects ──< criteria (name, scope: building|room, type: scale|binary, weight, emoji)
    │
    └──< buildings ──< building_scores  UNIQUE(building_id, criterion_id)
             │     └──< media
             │
             └──< rooms ──< room_scores  UNIQUE(room_id, criterion_id)
                      └──< media
```

사진·영상 파일은 앱 저장소로 복사하고 DB에는 경로만 둡니다. 갤러리·카메라가 주는 경로는 임시 파일이라 나중에 사라질 수 있어서예요. 영상 썸네일은 추가할 때 한 번만 뽑아 함께 저장합니다. 되돌리지 않은 삭제 때문에 남은 파일은 다음 실행 때 정리합니다.

## 시작하기

Flutter는 실제 기기가 필요해서 Docker 안에서 못 돌립니다 — 호스트에 SDK를 직접 설치해야 해요.

### 필요한 것

- [Flutter SDK](https://docs.flutter.dev/get-started/install)
- Android SDK 커맨드라인 도구 + JDK (Android Studio는 불필요)
- USB 디버깅 켠 실제 안드로이드 기기, 또는 에뮬레이터

### 실행

```bash
git clone https://github.com/dev1f965x/borogayo.git
cd borogayo
flutter pub get
flutter run
```

### 테스트

```bash
flutter analyze
flutter test
```

### 아이콘 · 스플래시

디자인 툴로 만든 이미지를 넣어두는 대신 코드로 그립니다. 브랜드 색이 바뀌면 파일 하나만 고치면 돼요.

```bash
dart run tool/generate_assets.dart
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

## 점수 계산

방의 점수는 **목록의 모든 기준**을 대상으로 한 가중 평균이고, 0~100으로 환산합니다.

**다 매기기 전에는 점수를 내지 않습니다.** 하나라도 비어 있으면 `—`로 두고, 순위에서만 0점으로 취급해 아래에 남깁니다.

절반만 본 집에도 숫자가 붙으면, 그 숫자가 "이 집의 값"인지 "여기까지 본 결과"인지 구분할 수 없습니다. 목록이 곧 순위인 화면에서는 그 애매함이 그대로 잘못된 판단이 돼요. 빈칸을 0점으로 채워서 계산해도 마찬가지입니다 — 낮게 나온 게 나쁜 집이라서인지 덜 봐서인지 알 수 없으니까요. 아예 점수를 안 내면 "아직 판단할 수 없음"이 화면에 그대로 남고, 다 보고 나면 그때 제자리를 찾습니다.

건물에는 점수가 없습니다. 건물 기준 점수는 그 안 방들의 점수에 그대로 합산되므로, 건물 평가가 안 끝났으면 방 점수도 나오지 않습니다. 이때는 방 카드가 "건물 평가를 마치면 점수가 나와요"라고 이유를 알려줍니다.

두 유형 모두 같은 0~10 척도로 저장되므로(없음=0, 있음=10) 계산식이 유형에 따라 갈라지지 않습니다. '없음'은 매긴 값이라 점수가 나오고, 안 건드린 것과는 다릅니다. 이 계산은 `lib/models/scoring.dart`에 순수 함수로 있고, DB 없이 따로 테스트합니다.
