# borogayo (보러가요)

[English](./README.md) | [한국어](./README.ko.md)

집 보러 다닐 때 쓰는 모바일 앱. 목록을 만들고, 무엇을 볼지 먼저 정해두고, 보러 간 집마다 같은 기준으로 점수를 매깁니다. 다섯 군데쯤 보고 나면 어디가 어땠는지 기억이 뭉개지는데, 그걸 기록으로 대체하는 게 목적이에요.

![Flutter](https://img.shields.io/badge/Flutter-3.47-02569B?logo=flutter&logoColor=white)
![Dart](https://img.shields.io/badge/Dart-3-0175C2?logo=dart&logoColor=white)
![SQLite](https://img.shields.io/badge/DB-SQLite-003B57?logo=sqlite&logoColor=white)

UI는 한국어 전용이고, 범용 체크리스트가 아니라 **주택 한정**으로 일부러 좁혔습니다. 채광·소음·수압·곰팡이·교통 같은 기본 항목이 미리 들어있는 게 핵심이에요 — "항목을 직접 정의하세요"라는 빈 화면이야말로 범용 도구가 안 쓰이게 되는 이유라서요.

## 기능

- **목록** — 이사 한 번에 하나씩 (예: "2026 봄 이사"). 목록을 만들 때 평가 기준을 함께 정하고, 집 볼 때 흔히 확인하는 것들이 미리 채워져 있습니다. 나중에 수정 가능.
- **건물 → 방** — 같은 건물에서 방 여러 개를 보는 경우가 많아서, 건물로 한 번 묶고 그 아래에 방을 넣습니다.
- **기준을 건물용/방용으로 분리** — 교통·주차·엘리베이터 같은 건물 기준은 **건물마다 한 번만** 매기고, 채광·소음·수압 같은 방 기준은 방마다 매깁니다. 안 나누면 "역 도보 8분"을 방마다 다시 매기게 되고, 그때마다 값이 미묘하게 달라져요.
- **두 가지 입력 방식** — 0~10 슬라이더(0.5 단위) 또는 있음/없음 토글. 둘 다 같은 0~10 척도로 저장되므로(없음=0, 있음=10) 가중합산 공식 하나로 전부 커버됩니다.
- **중요도** — 기준마다 1~5. 통근이 채광보다 더 크게 반영되도록 조절할 수 있어요.
- **순위** — 목록 안의 모든 방을 점수순으로 정렬하고 상위 3곳을 강조합니다. 방의 점수는 **그 건물 점수 + 방 자체 점수**예요. 건물 기준을 방마다 다시 매기지 않으니, 순위에서는 합쳐서 봐야 공정하니까요.
- **사진 · 영상** — 건물이나 방에 현장에서 찍어 붙이고, 구역(외관·주방·화장실…)을 태그로 달아 구분하고 걸러 볼 수 있습니다. 전체화면 보기 지원.
- **설정** — 밝게/어둡게/시스템 설정 따르기(기기에 저장), 앱 버전, 데이터 전체 삭제.

방 삭제는 스낵바에서 되돌릴 수 있고, 점수와 사진까지 함께 복구됩니다. 목록·건물·평가 기준처럼 여파가 큰 삭제는 되돌리기 대신 확인을 받고요. 채점 화면을 저장 없이 나가려 하면 한 번 물어봅니다.

모든 데이터는 기기 안에만 저장됩니다. 계정도, 서버도, 네트워크도 없어요.

## 데이터 모델

평가 기준이 목록마다 다르게 정의되므로, 점수를 통짜 JSON이 아니라 관계형으로 저장합니다. 그래야 나중에 가중치만 바꿔서 순위를 다시 계산해도 저장된 점수를 건드릴 필요가 없어요. 건물 점수와 방 점수는 테이블을 나눴는데, 한 테이블에 담으면 소유자 컬럼이 둘 다 널 허용이 되어 읽을 때마다 "어느 쪽 점수인지"를 확인해야 하기 때문입니다.

```
projects ──< criteria (name, scope: building|room, type: scale|binary, weight)
    │
    └──< buildings ──< building_scores  UNIQUE(building_id, criterion_id)
             │     └──< media
             │
             └──< rooms ──< room_scores  UNIQUE(room_id, criterion_id)
                      └──< media
```

사진·영상 파일은 앱 저장소로 복사하고 DB에는 경로만 둡니다. 갤러리·카메라가 주는 경로는 임시 파일이라 나중에 사라질 수 있어서예요. 되돌리지 않은 삭제 때문에 남은 파일은 다음 실행 때 정리합니다.

## 시작하기

Flutter는 실제 기기가 필요해서 Docker 안에서 못 돌립니다 — 호스트에 SDK를 직접 설치해야 해요.

### 필요한 것

- [Flutter SDK](https://docs.flutter.dev/get-started/install)
- Android SDK 커맨드라인 도구 + JDK (Android Studio는 불필요)
- USB 디버깅 켠 실제 안드로이드 기기, 또는 에뮬레이터

### 실행

```bash
git clone https://github.com/dev1f965x/borogayo.git
cd borogayo
flutter pub get
flutter run
```

### 테스트

```bash
flutter analyze
flutter test
```

## 점수 계산

방의 점수는 **실제로 매긴 기준만**을 대상으로 한 가중 평균이고, 0~100으로 환산합니다. 전체 기준 수로 나누면 덜 채점했다는 이유만으로 점수가 깎여서, 잠깐 보고 나온 집과 꼼꼼히 본 집을 비교할 수 없게 되거든요. 대신 후한 기준 하나만 매긴 방이 1위로 올라올 수 있어서, 순위에는 몇 개가 아직 미채점인지 함께 표시합니다.

두 입력 방식 모두 같은 0~10 척도로 저장되므로(없음=0, 있음=10) 계산식이 기준 타입에 따라 갈라지지 않습니다. 이 계산은 `lib/models/scoring.dart`에 순수 함수로 있고, DB 없이 따로 테스트합니다.
